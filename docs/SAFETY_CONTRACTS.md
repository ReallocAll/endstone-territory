# 领地状态与兼容性说明

## 坐标与面积

为兼容 0.4.2，正常输入的坐标小数保留在数据库中，运行时读取边界与传送点按向零截断解释。
面积恢复旧口径：先将各 X/Z 端点向零截断，再计算 `abs(x2-x1) * abs(z2-z1)`。
计费、限制、退款使用同一旧口径，计算使用 int64_t 避免溢出；单行/单列面积仍为零。
不自动改写旧数据库，也不会撤销玩家在 0.4.3 期间已提交的重圈或经济操作。
非法或非有限输入仍会被拒绝，不恢复旧版错误输入默认为原点的行为。
已有领地仍以当前配置价格退款，并非历史购买价。

坐标必须有限且在 ±30,000,000 内；新建/调整 Y 范围保持 -64..320。
即使 max_tty_area=-1，单轴 X/Z 跨度仍限制为 65,535，单领地最多覆盖 4,096 个 128×128
索引格。非法旧数据使载入失败并保留原缓存，不静默忽略领地保护。

## 数据库、缓存与经济

- 名称检索使用绑定参数。引号和标点是数据，不是 SQL。
- 重命名及子领地关联、删除及子领地解绑、调整范围及传送点都在一个 SQLite 事务中完成。
  失败或 COMMIT 失败回滚；目标不存在不报告成功。
- 上述修改先准备完整缓存和空间索引，提交后无异常交换；查询失败不清空旧缓存。
  常规位置事件继续只查询空间网格，子领地优先级保留。
- 创建/扩大领地先检查扣款返回值；已知失败不继续修改。修改失败的补偿检查返回值并报告。
  缩小领地提交后才退款。删除与退款意图写入同一 SQLite 事务，提交后才尝试退款。
- `territory_economy_operations` 保留 operation ID、玩家、金额、原因及
  `pending / attempting / succeeded / failed`。同一 ID 最多调用经济提供者一次。
  `pending` 或 `attempting` 未解决时拒绝该玩家新的经济操作。
- MoneyConnect 不支持幂等键或跨库事务。崩溃可能发生在扣款与创建之间、调整提交与退款意图之间，
  或支付已发生但完成记录未写入时。因此这不是跨系统原子提交，也不承诺崩溃后自动恢复。
  `attempting` 的实际支付结果未知，必须查经济提供者流水；不要自动重试、自动反向转账或删除审计行。
  管理员核对领地、审计 ID 与提供者流水后人工修复；失败/未决退款会在服务端日志提示，在线领地主也会收到错误。
  保留和归档审计记录由管理员按运营要求处理。

## 活塞保护

恢复 0.4.2 的既有策略：只检查活塞本体所在的领地和原有约一格边缘规则。
保持空间索引、维度隔离、子领地优先及 `if_edge_piston` 权限语义。
移除 0.4.3 的 XYZ 各 ±13 包围盒拦截；低矮或狭长领地中的正常内部机器不再因此整片停机。

这不是精确的跨领地推动保护：当前 SDK 没有实际移动方块列表，因此不能保证阻止领地外活塞
推动方块进入领地。兼容修复不再用扩大禁用范围来弥补该 API 限制，也不修改原版活塞推动机制。
不要通过批量删地或重圈修复；更换插件即可恢复判定规则，已改动的范围需单独核对备份。

## 飞行与会话

飞行默认关闭。现在还需要 `fly_exclusive_authority: true` 明确声明 Territory 是生存/冒险模式
飞行能力的唯一管理者。其他插件也管理飞行时不要启用；共享 `allowFlight` 布尔值无法区分后来
授予的能力。未声明独占时 Territory 不更改飞行能力，并记录提示。

独占模式只回收本会话中由 Territory 从 false 改为 true 的授权，不关闭玩家进入前已有的飞行。
创造/旁观模式不回收；退出、重载和停用清理本插件授权及位置/快速创建会话状态。
位置比较包含维度，跨维度绕过节流；移动与传送只处理未取消事件。

## 验证

`cmake --build build` 后运行 `ctest --test-dir build -C Release --output-on-failure`。
原生 C++ 契约测试使用真实 SQLite、实际 claim/index 实现以及可注入的经济结果，覆盖事务中断、
标点名称、精确身份、子领地缓存、旧版坐标/面积兼容、维度和活塞边缘策略、飞行授权所有权。
这些测试不模拟完整 BDS、实际经济插件或玩家事件时序。Linux 插件必须使用 Endstone 要求的
Clang/libc++；GCC 只能用于源码/合成契约检查，不能作为可部署 BDS 插件。

Fork 的 push 运行构建和测试；仅格式为 `chore: release vX.Y.Z` 的版本提交或匹配的版本标签在 Linux/Windows 构建和契约测试都通过后校验 CMake 版本与 CHANGELOG 后发布不可变版本标签。不会删除或重建 nightly 标签。发布包含确切提交、CI URL 与 SHA-256 校验值。
